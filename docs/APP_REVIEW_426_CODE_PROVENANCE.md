# Meetopia: code provenance and App Review 4.2.6 evidence

Status: **internal, evidence-based draft. NOT a statement submitted to Apple.**
Reviewed: 2026-11-17.

## What the repository actually establishes

- GitHub repository `BTheCoderr/MeetopiaAPP` was created on 2024-12-19, is **not** a GitHub fork, and has `is_template: false` as of this review.
- Earliest visible root commit: `81d038cd`, **2025-01-15**, by `BTheDream`, entitled "Initial commit: Meetopia app with video, text, and combined chat features." This was a Meetopia-specific video/text chat project, not the current dating application.
- The initial code already had custom pages/routes for Meetopia, Socket.IO chat and server code. The initial README and package manifest contained broad/generic Next.js setup language, and the tree contained default Next.js SVGs, `node_modules` and two assistant snippet text files. **These are evidence of generic tooling/scaffolding, NOT proof of a purchased dating-app template.** Do not claim every file was authored line by line without scaffolding.
- Subsequent commits show incremental development of authentication, signaling, video interactions, saved Connections, blocks/reports and the native Expo client. The current draft includes multi-party consent, Chemistry Passports, three interactive Vibe Rounds, Encore, Spark Cards and protocol release safeguards.
- The current application stack uses **general-purpose frameworks and packages** (Next.js, React, Expo/React Native, Expo Router, WebRTC, Socket.IO, Prisma/PostgreSQL). They are not commercialized dating-app templates merely because other applications use those packages.
- The current native bundle is configured as `com.meetopia.app` and points to the Meetopia APIs. The repo includes an older checked-in native `ios/` tree, but EAS config uses Continuous Native Generation and excludes that tree from the cloud build archive. **The archive still needs actual inspection** before Apple submission.
- Earlier versions of the native app contained simulated profiles and local-only demos. These are no longer the intended current native experience; their presence in an *old rejected binary* must be disclosed accurately. No assertion is made about code not in the repository, external asset licenses, or actual device builds.

## What this audit did NOT establish

- It cannot prove that no person ever copied code from a third-party app, or establish the licensing/provenance of every PNG asset.
- It does not inspect every former vendor download, private repository or conversation.
- It does not independently confirm the identity/legal entity that owns Meetopia's concept, content, brand and Apple Developer account.
- It cannot inspect other apps on that Apple Developer account or whether significant proprietary code/assets are reused between them.
- It does not establish whether the original artwork was designed from scratch, created with an AI image tool, generated by Expo scaffolding, or licensed. Asset provenance needs confirmation from the creator.
- It does not verify whether the current draft was ever installed on an iPhone or submitted to Apple. Passing CI is not TestFlight feedback.

## User-reported project history (verify before Apple submission)

The project owner reports commissioning/developing this app with help from ChatGPT/AI coding assistants, **not** buying or licensing a commercial white-label dating application. This user report is consistent with the visible GitHub history; the GitHub history alone cannot prove the absence of any external code sources.

Using a general-purpose AI coding assistant to help write application code is distinct from purchasing a commercial dating template or reskinning a provider-owned app. Apple Guideline 4.2.6 applies to **commercialized templates and app-generation services** and requires submission directly by the provider of the app's content. Read alongside Guideline 4.3(b), which independently requires dating apps to be meaningfully different or improved.

Official guidelines: https://developer.apple.com/app-store/review/guidelines/#4.2
and https://developer.apple.com/app-store/review/guidelines/#4.3

# Meetopia production QA — September 29, 2026

Tested the canonical Netlify app and Render signaling service after the Prisma
table lock in `8c3030e7`. Tests used three temporary accounts, including an
unrelated account for authorization checks. Those accounts, their sessions,
messages, notifications, report, and block were removed afterward; the final
query returned zero remaining QA accounts.

## Production checks passed

- Fresh signup and sign-in create usable server sessions.
- Anonymous callers cannot list Connections.
- Signed Socket.IO authentication works through HTTP polling.
- Two QA users match and mutual Vibe persists a single shared Connection.
- An unrelated account cannot read the Connection or its messages.
- Presence, persisted messages, realtime delivery, notifications, and read state work.
- Call Again sends an incoming invitation; accepting pairs the two accounts.
- Web reports persist through Prisma.
- Blocking removes the Connection and denies subsequent HTTP messages and call proofs.
- All 11 Prisma-managed public tables retain RLS and deny anon/authenticated table access.

These are API/signaling checks, not a two-device audio/video test. Native
WebSocket transport could not connect from this execution environment; the
polling transport completed the test. iPhone camera controls, media delivery,
TURN across Wi-Fi/cellular, and screen sharing still require device testing.

## Recovery fix

PR #23 fixes the signed-out redirect loop for forgot/reset password pages.
The production forgot-password page now returns HTTP 200. The build and
middleware checks passed; Connections remains protected. Email delivery and
password reset completion were not exercised.

## Realtime authorization follow-up

Code review found that cached realtime/Call Again proofs were trusted without
checking the current Connection and block state. Client-supplied message content
was also relayed without loading the saved message.

The follow-up introduces a server-authenticated Prisma validation endpoint.
Render checks current Connection access before relaying private events and before
starting/accepting a direct call. Messages and read receipts come from saved
database rows. Validation failures deny the event. No browser database grants
or policies are changed.

Five local regression tests cover revoked proofs, forged message content,
unpersisted messages, revocation while a call rings, valid calls/reads, and gateway
authentication. CI runs these tests with the web build.

### Rollout

Deploy the new web endpoint on Netlify before deploying the updated signaling
server. The server uses the existing shared `SOCKET_AUTH_SECRET` and defaults
`WEB_APP_URL` to the canonical production app. Local development must set
`WEB_APP_URL` to the local Next.js server. Verify the new route and rerun the
production flow after both deployments; fail-closed behavior means realtime
events will stop if Render cannot reach the endpoint.

Render's public health response reported Supabase/email report delivery disabled
and JSONL fallback enabled during this pass. Web report persistence passed, but
the separate Render reporting configuration needs inspection before relying on
its durable storage. Render workspace selection requires confirmation through
the connector.
